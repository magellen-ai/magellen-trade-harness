# 愿景：全天候 Trading Agent 工作区

本仓库的目标，是提供一个可以长期运行 Trading Agent 的工作区与运行基础设施。

一个实例由一个配置目录初始化而来。配置主要决定：

- 使用哪个 Agent runtime（例如 Pi、Grok、Claude）；
- 使用哪些数据、研究和交易工具；
- 这些工具如何安装、注入环境并启动。

投资目标、研究方法、决策循环、记忆组织和调度习惯，优先通过工作区内的 `AGENTS.md`、`CLAUDE.md`、skill、memory 和其他文档表达。它们是给 Agent 阅读和执行的工作材料，不应过早硬编码成框架配置或强类型领域模型。

当前的单市场、单交易接口、简单策略，只是用来验证工作区闭环的实验。平台的长期价值在于：可以用同一套基础设施创建不同的投资实例，并让实例在长期运行中自行研究、行动、记录和安排下一次工作。

## 设计取向

- **Agent 优先**：框架提供工具和上下文，保留 Agent 自主组合能力。
- **薄封装**：市场数据、研究源和交易接口优先保留各自特性，用 CLI、skill 和少量 wrapper 暴露能力。
- **配置克制**：配置选择 runtime、工具来源和启动方式；不要把投资知识和策略流程变成配置字段。
- **工作区优先**：长期方法、风险边界、研究流程、记忆和实例说明写入工作区文件。
- **渐进增强**：先跑通真实闭环，再根据重复出现的痛点增加程序化能力。
